# Working agreement

Three roles divide the work on this repository. They are roles, not people or
processes: one contributor may hold all three, but the *hats are not worn at
the same time*, because the whole point of the split is that the person
building the estimator is not the person deciding whether it was fooled.

Every change should be attributable to one of the three. A change that belongs
to none of them probably does not belong in this repository — see
[`docs/SCOPE.md`](docs/SCOPE.md).

---

## Agent A — Statistical Auditor

**Owns the question "what does this number mean?"** Produces specifications,
not code. Anything Agent A settles becomes binding on Agent B.

Agent A's outputs live in `docs/`:

| Decision | Recorded in |
|---|---|
| Unit of inference | `STATISTICAL_PROTOCOL.md` §1 |
| Nesting structure and what may never be a replicate | `STATISTICAL_PROTOCOL.md` §2 |
| Primary and secondary metrics, and their levels | `METRIC_REGISTRY.md` |
| Bootstrap design: unit, method, resamples, seeds | `STATISTICAL_PROTOCOL.md` §5 |
| Equivalence methodology and how margins are set | `STATISTICAL_PROTOCOL.md` §6 |
| Missing-data rules | `STATISTICAL_PROTOCOL.md` §7 |
| Assumptions that must hold | `ASSUMPTIONS.md` |
| Decisions and rejected alternatives | `DECISIONS.md` |

**Standing obligations**

- Name the estimand before the estimator. "Mean loss" is not an estimand;
  "the mean, over events, of the per-event mean loss, over the population of
  worlds the sampled worlds represent" is.
- Never allow a default margin. A margin that nobody chose is a margin nobody
  will defend.
- When a design cannot answer a question, say so in the protocol rather than
  letting the analysis produce a number anyway.

## Agent B — Implementation Engineer

**Owns the question "does the code do what the protocol says?"** Builds and
maintains the library in `src/wg_eval/`.

**Standing obligations**

- Implement what the protocol specifies. Where the code must choose something
  the protocol left open, either raise (preferred) or implement the
  conservative option and open a decision for Agent A.
- Make invalid analyses hard to express. `bootstrap.cluster_level: resident`
  is rejected at config load; equivalence without a margin raises
  `MarginRequired`. A warning in the docs is not a guard.
- Every result-producing path attaches provenance. A number without a
  fingerprint is a bug, not a cosmetic issue.
- Keep the library domain-free. If a symbol, comment or default would not make
  sense to someone evaluating drug trials or A/B tests, it does not belong in
  `src/`.
- New estimators go through `register_estimator` with a definition template, so
  the definition travels into provenance automatically.

## Agent C — Red Team

**Owns the question "what would fool this?"** Builds datasets designed to make
a competent analysis reach a wrong conclusion, in `src/wg_eval/synth/`.

**Standing obligations**

- Every scenario ships three things: records with a truth known by
  construction, the misleading analysis the records reward, and the correct
  analysis that recovers the truth.
- A scenario asserts **both** directions. `trap_reproduced` must be true — if
  the wrong analysis is not actually fooled, the scenario is not testing
  anything — and `defence_worked` must be true.
- Prefer measurement to rhetoric. "The naive interval is too narrow" is an
  opinion; "its nominal-95% interval covers the truth 62% of the time over 100
  replications" is a result. See `coverage_study`.
- When a defence fails, the finding goes to Agent A as a protocol question
  before it goes to Agent B as a bug.

## How the roles interact

```
Agent A  --specification-->  Agent B  --library-->  Agent C
   ^                                                    |
   |                  finding that breaks a defence     |
   +----------------------------------------------------+
```

A red-team finding never goes straight to a code patch. It goes to the
protocol first, because a scenario that fools the library usually means the
protocol under-specified something, and patching the code alone leaves the
next version of the same trap open.

## Conventions

- **Tests** mirror the modules: `test_schema_and_validation.py`,
  `test_metrics_and_aggregation.py`, `test_pairing_and_bootstrap.py`,
  `test_equivalence.py`, `test_compare_and_stratify.py`,
  `test_io_provenance_report.py`, `test_cli.py`, `test_redteam.py`,
  `test_fixtures.py`.
- **Slow tests** (coverage studies, scenario replications) carry
  `@pytest.mark.slow`. They are part of the default run; `-m "not slow"` skips
  them during iteration.
- **Fixtures** are generated by `tests/fixtures/generate_fixtures.py` and
  committed, with a `MANIFEST.json` recording each one's checksum and truth.
  `test_fixtures.py` fails if the generator and the committed bytes diverge.
- **Seeds** are explicit everywhere. A default seed of 0 is fine; an absent
  seed is not.
- **Task state** lives in `tasks/CURRENT.md` (in flight),
  `tasks/ROADMAP.md` (ordered, not yet started) and `tasks/COMPLETED.md`
  (done, with what was actually delivered).
